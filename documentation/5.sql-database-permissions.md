# Configuring Azure SQL Database Permissions

## Overview

The `database-permissions/` Terraform configuration manages database-level permissions for the eShopOnWeb application.

After the main infrastructure has been deployed, both App Services have system-assigned Managed Identities that need access to the Azure SQL databases.

This configuration establishes the database users and assigns the required roles to the following identities:

- **Web MVC:** `eshop-dev-webmvc`
- **Public API:** `eshop-dev-publicapi`

Both identities require access to:

- `CatalogDb`
- `IdentityDb`

The configuration separates database authorization from the main infrastructure deployment, making database permissions independently manageable.

## Prerequisites

Before deploying database permissions, ensure that:

- The bootstrap infrastructure has been deployed.
- Azure Key Vault has been configured.
- The main infrastructure has been successfully deployed.
- Both App Service Managed Identities exist.
- The Terraform remote backend configuration (`backend.hcl`) is available.
- The executing Azure identity has sufficient permissions to manage database users and roles.

Authenticate with Azure:

```powershell
az login
```

Select the appropriate subscription:

```powershell
az account set --subscription "<SUBSCRIPTION_ID>"
```

## Deploy Database Permissions

Navigate to the database permissions directory:

```powershell
cd ../database-permissions
```

**1. Initialize Terraform**

Initialize Terraform and configure the remote backend:

```powershell
terraform init -backend-config="backend.hcl"
```

**2. Validate the configuration**

```powershell
terraform validate
```

**3. Review the execution plan**

```powershell
terraform plan
```

Review the planned database permission changes before proceeding.

**4. Apply the database permissions**

```powershell
terraform apply
```

Confirm the deployment when prompted.

## Expected Outcome

After successful deployment:

- Both App Service Managed Identities have corresponding database users.
- The identities receive the configured database roles in `CatalogDb` and `IdentityDb`.
- The Web MVC and Public API applications can authenticate to Azure SQL using Managed Identity, subject to the required network and SQL configuration.

## Important Notes

- This configuration manages database authorization independently of the main infrastructure.
- Both App Services must already exist because their Managed Identities are required.
- Review the Terraform plan before applying permission changes.
- Database permissions should follow the principle of least privilege. Assign only the roles required by the applications.
- If database users need to be recreated using Azure SQL's native `FROM EXTERNAL PROVIDER` functionality, refer to the separate `DATABASE-USER-RECREATION.md` procedure.

Once this step is complete, the eShopOnWeb infrastructure and database authorization are configured.
