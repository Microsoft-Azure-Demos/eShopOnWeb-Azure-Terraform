# Deploying Azure Key Vault – Persistent Security Infrastructure

## Overview

The key-vault/ Terraform configuration provisions persistent security infrastructure independently of the eShop application resources.

Azure Key Vault securely stores sensitive application secrets, such as the JWT signing key used by the eShop applications.

Keeping Key Vault separate from the application infrastructure provides an important benefit during development and testing: secrets only need to be configured once and remain available across application infrastructure redeployments. This avoids having to recreate or manually configure the JWT signing key every time the application infrastructure is destroyed and redeployed.

For production environments, Key Vault provisioning could alternatively be integrated into the main infrastructure deployment, depending on the organization's security requirements, infrastructure lifecycle strategy, and deployment architecture.

The configuration provisions:

- **Resource Group:** Dedicated resource group for security infrastructure.
- **Azure Key Vault:** Secure storage for application secrets.
- **Random Suffix:** Ensures the Key Vault name is globally unique.
- **RBAC Role Assignment:** Grants the currently authenticated Azure identity the `Key Vault Secrets Officer` role to manage secrets.

Key Vault is configured with:
- Azure RBAC authorization enabled.
- Purge protection enabled.
- Standard SKU.
- Persistent environment and project tags.

## Prerequisites

- Azure CLI installed.
- Terraform installed.
- An authenticated Azure CLI session.
- Sufficient Azure permissions to create resources and assign RBAC roles.

Authenticate with Azure:

```powershell
az login
```

Select the appropriate subscription:

```powershell
az account set --subscription "<SUBSCRIPTION_ID>"
```

## Deploy Key Vault

Run the following commands from the `key-vault/` directory.

**1. Initialize Terraform**

If remote state is configured:

```powershell
terraform init -backend-config="backend.hcl"
```

**2. Review the deployment plan**

```powershell
terraform plan
```

**3. Deploy the resources**

```powershell
terraform apply
```

Confirm the deployment when prompted.

## Configure the JWT Signing Key

After Key Vault has been created, add the JWT signing key as a secret.

Example using Azure CLI:

```powershell
az keyvault secret set `
  --vault-name "<KEY_VAULT_NAME>" `
  --name "jwt-signing-key" `
  --value "<JWT_SIGNING_KEY>"
```

Replace the placeholders with the actual Key Vault name and signing key.

The JWT signing key is used to sign and validate authentication tokens. It must remain secret because anyone possessing it could potentially create valid tokens.

## Application Access

The eShop App Services access the JWT signing key through their system-assigned Managed Identities.

The infrastructure configuration assigns the `Key Vault Secrets User` role to the respective App Service identities, allowing them to retrieve the secret.

The application setting references the secret using a Key Vault reference:

```text
@Microsoft.KeyVault(SecretUri=https://<KEY_VAULT_NAME>.vault.azure.net/secrets/jwt-signing-key)
```

App Service resolves this reference using its Managed Identity and exposes the resolved value to the application as an application setting.

## Important Notes

- Deploy Key Vault before the main application infrastructure.
- Keep Key Vault separate from the application infrastructure lifecycle.
- Do not store the JWT signing key in Terraform variables, `.tfvars` files, or source control.
- Purge protection helps prevent permanent deletion of the Key Vault and its secrets during the configured protection period.
- The `Key Vault Secrets Officer` role allows the authenticated deployment identity to manage secrets; it does not automatically grant application identities access.
- Ensure the App Service Managed Identities have the `Key Vault Secrets User` role before expecting Key Vault references to resolve.

Once deployed and configured, Key Vault provides persistent secret management for the eShop application infrastructure.
