# Verifying the eShopOnWeb Azure Deployment

## Overview

After completing the Terraform deployment, use Azure CLI to verify that the main eShopOnWeb resources have been successfully provisioned.

The following checks cover the App Services, App Service Plan, SQL databases, and Storage Account.

## Prerequisites

- Azure CLI installed.
- An authenticated Azure CLI session.
- Access to the Azure subscription containing the eShopOnWeb resources.

Authenticate with Azure:

```powershell
az login
```

Select the appropriate subscription:

```powershell
az account set --subscription "<SUBSCRIPTION_ID>"
```

## 1. Verify App Services

List the App Services deployed in the resource group:

```powershell
az webapp list `
  --resource-group eshop-dev-rg `
  --output table
```

Verify that both applications are listed:

- `eshop-dev-webmvc`
- `eshop-dev-publicapi`

## 2. Verify the App Service Plan

Check that the App Service Plan has been created:

```powershell
az appservice plan list `
  --resource-group eshop-dev-rg `
  --output table
```

Expected resource:

- `eshop-dev-asp`

## 3. Verify SQL Databases

List the databases hosted on the Azure SQL logical server:

```powershell
az sql db list `
  --resource-group eshop-dev-rg `
  --server eshop-dev-sql-server `
  --output table
```

Verify that both databases are available:

- `CatalogDb`
- `IdentityDb`

## 4. Verify the Storage Account

Check the application Storage Account:

```powershell
az storage account show `
  --name eshopdevstorage `
  --resource-group eshop-dev-rg `
  --output table
```

Verify that the Storage Account exists and its provisioning state is `Succeeded`.

## 5. Verify Application Endpoints

After confirming that the resources exist, test the application endpoints.

```powershell
# Test the Web MVC application.
curl.exe -I https://<WEB_MVC_HOSTNAME>/

# Test the Public API application.
curl.exe -I https://<PUBLIC_API_HOSTNAME>/
```

Replace the placeholders with the actual App Service hostnames.

A successful HTTP response confirms that the endpoint is reachable. An HTTP error response may indicate an application, authentication, or configuration issue that requires further investigation.

## Expected Outcome

The verification process should confirm that:

- Both App Services exist.
- The App Service Plan is provisioned.
- Both SQL databases are available.
- The application Storage Account exists.
- The application endpoints are reachable.

These checks provide an initial overview of the deployed infrastructure. They do not replace application-level testing or verification of database connectivity, Managed Identity permissions, and Key Vault references.
