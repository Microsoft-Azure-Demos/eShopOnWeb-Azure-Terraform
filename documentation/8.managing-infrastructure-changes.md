# Managing Infrastructure Changes with Terraform

## Overview

Terraform manages the lifecycle of the Azure infrastructure through Infrastructure as Code (IaC).

Instead of manually modifying Azure resources through the portal, infrastructure changes are defined in Terraform configuration files and applied through Terraform commands.

This provides a consistent, repeatable, and traceable approach to infrastructure management.

## 1. Review Infrastructure Changes

Before applying any changes, generate and review the Terraform execution plan:

```powershell
terraform plan
```

The plan identifies resources that Terraform intends to:

- Create
- Modify
- Destroy

Always review the proposed changes before proceeding.

## 2. Apply Infrastructure Changes

Apply the approved configuration:

```powershell
terraform apply
```

Terraform executes the planned operations and updates the remote state accordingly.

## 3. Inspect Managed Resources

List all resources currently tracked by the Terraform state:

```powershell
terraform state list
```

This is useful for understanding which Azure resources are managed by a particular Terraform configuration.

## 4. Inspect an Individual Resource

Display the attributes and configuration recorded for a specific resource:

```powershell
terraform state show <RESOURCE_ADDRESS>
```

Example:

```powershell
terraform state show azurerm_mssql_server.sql_server
```

Use the resource addresses returned by `terraform state list`.

## 5. Import Existing Azure Resources

When an Azure resource already exists but is not tracked in the Terraform state, it can be imported:

```powershell
terraform import <RESOURCE_ADDRESS> <AZURE_RESOURCE_ID>
```

Example:

```powershell
terraform import azurerm_service_plan.eshop "/subscriptions/<SUBSCRIPTION_ID>/resourceGroups/eshop-dev-rg/providers/Microsoft.Web/serverFarms/eshop-dev-asp"
```

Importing connects an existing Azure resource to a Terraform resource address. The corresponding resource configuration must already exist in the Terraform code.

After importing, run:

```powershell
terraform plan
```

Review any differences between the existing Azure resource and the Terraform configuration.

## 6. Important Considerations

- Keep Terraform configuration and remote state synchronized.
- Review execution plans before applying changes.
- Use `terraform import` when adopting existing resources into Terraform management.
- Avoid manually deleting Terraform-managed resources without reconciling the Terraform state.
- Be careful when using `terraform state rm`: it removes a resource from Terraform state without deleting the actual Azure resource.
- Protect the remote state because it contains important information about the managed infrastructure.

Following these practices helps maintain consistency between the Terraform configuration, remote state, and deployed Azure resources.
