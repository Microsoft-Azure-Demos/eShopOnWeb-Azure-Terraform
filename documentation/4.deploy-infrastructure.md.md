# Provisioning the Main eShopOnWeb Infrastructure

## Overview

The `infrastructure/` Terraform configuration provisions the main Azure resources required to run the eShopOnWeb application.

It brings together reusable Terraform modules and environment-specific configuration to deploy the application infrastructure.

The deployment includes:

- **Resource Group:** Hosts the eShop application resources.
- **App Service Plan:** Provides the compute resources for the Web MVC and Public API applications.
- **Azure App Services:** Hosts the containerized Web MVC and Public API applications.
- **Azure SQL Server and Databases:** Provides the database infrastructure for `CatalogDb` and `IdentityDb`.
- **Azure Storage Account:** Stores product images and related application assets.
- **Managed Identities and RBAC:** Provides secure access to Azure resources.
- **Key Vault Integration:** Configures application access to the JWT signing key stored in Azure Key Vault.

The configuration uses reusable Terraform modules to separate infrastructure logic from environment-specific settings. Application settings are maintained separately in JSON files under `app-settings/`.

## Prerequisites

Before deploying the main infrastructure, ensure that:

- The bootstrap infrastructure has been deployed.
- Azure Key Vault has been created and the required JWT signing key has been configured.
- The required Terraform backend configuration (`backend.hcl`) is available.
- Azure CLI and Terraform are installed.
- You are authenticated to the correct Azure subscription.

Authenticate with Azure:

```powershell
az login
```

Select the appropriate subscription:

```powershell
az account set --subscription "<SUBSCRIPTION_ID>"
```

## Deploy the Main Infrastructure

Navigate to the infrastructure directory:

```powershell
cd ../infrastructure
```

**1. Initialize Terraform**

Initialize Terraform and configure the Azure Blob Storage remote backend:

```powershell
terraform init -backend-config="backend.hcl"
```

**2. Validate the configuration**

Check the Terraform configuration for syntax errors and internal consistency:

```powershell
terraform validate
```

**3. Review the execution plan**

Preview the resources Terraform intends to create, modify, or destroy:

```powershell
terraform plan
```

Review the planned changes carefully before proceeding.

**4. Apply the infrastructure**

Deploy the Azure resources:

```powershell
terraform apply
```

Confirm the deployment when prompted.

## Post-Deployment

After successful deployment:

- Verify that both App Services have been provisioned.
- Check that the container images are configured correctly.
- Verify that the system-assigned Managed Identities are enabled.
- Confirm that the Key Vault references have resolved successfully.
- Verify that the Azure SQL databases and Storage Account are available.
- Test the Web MVC and Public API application endpoints.

The separate `database-permissions/` configuration is responsible for configuring the SQL database permissions for the App Service Managed Identities.

## Important Notes

- The infrastructure uses the remote state configured in `backend.hcl`.
- Application settings are maintained in separate JSON files for Web MVC and Public API.
- The Key Vault signing key is managed independently and should persist across application infrastructure redeployments.
- Review every Terraform plan before applying changes, particularly when modifying or destroying existing resources.
- Avoid manually modifying Terraform-managed resources in Azure because this can introduce configuration drift.

Once deployed, the main infrastructure provides the Azure resources required to host and operate the eShopOnWeb applications.
