# Configuring Terraform Remote State with Azure Blob Storage

## Overview

Terraform uses a state file (`terraform.tfstate`) to keep track of the infrastructure resources it manages, including their Azure resource IDs, attributes, and relationships.

For the eShopOnWeb Azure project, **Azure Blob Storage** is used as a remote backend to store Terraform state instead of keeping it exclusively on the local machine.

The following command initializes Terraform using the backend configuration defined in `backend.hcl`:

```powershell
terraform init -backend-config="backend.hcl"
```

## 1. Remote State Architecture

The remote state architecture consists of two main components:

**Local Machine**
- Terraform configuration files (`.tf`)
- Backend configuration (`backend.hcl`)
- Terraform commands (`init`, `plan`, and `apply`)

**Azure Storage Account**
- Blob container: `tfstate`
- Stores the remote Terraform state file

Terraform communicates with Azure Blob Storage to read and update the state file whenever infrastructure operations require it.

## 2. Create the Azure Storage Resources

Before configuring the remote backend, the following Azure resources must exist:

- **Resource Group:** Contains the Terraform state resources.
- **Storage Account:** Provides Azure Blob Storage.
- **Blob Container:** Stores the Terraform state files.

These resources form the foundation for remote state management and should be created before initializing the backend.

## 3. Configure `backend.hcl`

Inside each Terraform environment directory, create a file named `backend.hcl`.

Example configuration:

```hcl
# Configure Azure Blob Storage as the remote Terraform state backend.

resource_group_name  = "terraform-state-rg"
storage_account_name = "eshopterraformstate"
container_name       = "tfstate"
key                  = "eshop-infrastructure.tfstate"
```

### Backend configuration parameters

| Setting | Purpose |
|---|---|
| `resource_group_name` | Resource group containing the Storage Account |
| `storage_account_name` | Name of the Azure Storage Account |
| `container_name` | Blob container that stores the state |
| `key` | Name of the Terraform state blob |

### Managing multiple state files

The `key` parameter allows different Terraform configurations to maintain independent state files within the same Blob container.

For example:

| Terraform configuration | State key |
|---|---|
| Infrastructure | `eshop-infrastructure.tfstate` |
| Key Vault | `eshop-key-vault.tfstate` |
| Database permissions | `eshop-database-permissions.tfstate` |

Each Terraform root module should use its own backend key to prevent unrelated infrastructure configurations from sharing the same state.

## 4. Declare the Terraform Backend

Add the following backend declaration to `providers.tf` or another `.tf` file in the Terraform root module:

```hcl
# Declare Azure Blob Storage as the backend; configuration is supplied through backend.hcl.

terraform {
  backend "azurerm" {}
}
```

The backend block is intentionally empty because the configuration parameters are supplied separately through `backend.hcl`.

This separation keeps backend configuration outside the reusable Terraform infrastructure code.

## 5. Initialize Terraform

Run the following command from the directory containing the Terraform configuration and `backend.hcl`:

```powershell
terraform init -backend-config="backend.hcl"
```

During initialization, Terraform:

1. Initializes the Azure Storage backend.
2. Authenticates to Azure using the configured authentication method.
3. Connects to the specified Storage Account and Blob container.
4. Configures remote state management.
5. Retrieves the existing remote state, if one is already available.

### Migrating existing local state

If Terraform already manages infrastructure using a local state file, initializing the remote backend may prompt you to migrate the existing state.

Choose the option to copy the existing state to the remote backend.

This ensures that Terraform continues managing the existing infrastructure using the migrated state.

> **Important:** `terraform init` configures the backend. It does not create or deploy Azure infrastructure resources.

## 6. Verify the Remote State

After successfully running `terraform apply`, verify that the state file exists in the Azure Blob container.

Using Azure CLI:

```powershell
az storage blob list `
  --account-name $STORAGE_ACCOUNT `
  --container-name $CONTAINER `
  --auth-mode login `
  --output table
```

The output should contain a blob corresponding to the configured state key, for example:

```text
eshop-infrastructure.tfstate
```

This confirms that Terraform is storing its state remotely in Azure Blob Storage.

## 7. Security Considerations

Terraform state files may contain sensitive infrastructure information and application configuration values. Protecting access to the remote state is therefore essential.

Recommended practices:

- Do not commit `backend.hcl` if it contains credentials or other sensitive values.
- Add `backend.hcl` to `.gitignore`.
- Prefer Microsoft Entra ID authentication over storing Storage Account access keys in configuration.
- Enable Blob Storage versioning to retain previous versions of the state file.
- Consider enabling soft delete to protect against accidental deletion.
- Restrict access to the Storage Account and Blob container using appropriate Azure RBAC permissions.
- Never commit Terraform state files or sensitive credentials to source control.

---

## Summary

Using Azure Blob Storage as a Terraform remote backend provides centralized state management for the eShopOnWeb infrastructure.

It also enables multiple team members or deployment environments to work with a shared remote state rather than relying on individual local state files.

The use of separate backend keys ensures that infrastructure, Key Vault, and database permission configurations maintain independent Terraform states.
