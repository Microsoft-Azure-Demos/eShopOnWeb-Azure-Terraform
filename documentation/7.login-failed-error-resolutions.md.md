# Recreating Azure SQL Users for App Service Managed Identities

## 1. Background

During the deployment of the eShopOnWeb application, both App Services use their system-assigned Managed Identities to authenticate against Azure SQL Database.

Initially, the database users were created using the Terraform `mssql_azuread_user` resource. However, the application encountered the following authentication error:

```text
Login failed for user '<token-identified principal>'
```

The issue was traced to a mismatch between the SID stored for the database users and the authoritative SID associated with their Microsoft Entra ID identities.

Azure SQL Database authenticates Managed Identity tokens using the identity's SID. To resolve the mismatch, the existing database users were removed and recreated using Azure SQL's native `FROM EXTERNAL PROVIDER` functionality.

This allows Azure SQL to resolve the identities through Microsoft Entra ID and create the database users with the correct identity information.

## 2. Remove the Existing Database Users

Execute the following SQL script in **both `CatalogDb` and `IdentityDb`**.

```sql
-- Remove the existing App Service Managed Identity users if they exist.

DROP USER IF EXISTS [eshop-dev-webmvc];
DROP USER IF EXISTS [eshop-dev-publicapi];
```

## 3. Verify User Deletion

Before recreating the users, verify that both database principals have been completely removed.

```sql
-- Verify that neither Managed Identity user remains in the database.
-- The query should return zero rows.

SELECT
    name,
    type_desc,
    authentication_type_desc,
    create_date
FROM sys.database_principals
WHERE name IN (
    N'eshop-dev-webmvc',
    N'eshop-dev-publicapi'
);
```

The expected result is an empty result set.

## 4. Recreate the Database Users

Create both database users using `FROM EXTERNAL PROVIDER` and assign the required database roles.

```sql
-- Recreate both App Service Managed Identity users and assign database roles.

-- Web MVC Managed Identity
CREATE USER [eshop-dev-webmvc] FROM EXTERNAL PROVIDER;

ALTER ROLE db_datareader ADD MEMBER [eshop-dev-webmvc];
ALTER ROLE db_datawriter ADD MEMBER [eshop-dev-webmvc];
ALTER ROLE db_ddladmin ADD MEMBER [eshop-dev-webmvc];


-- Public API Managed Identity
CREATE USER [eshop-dev-publicapi] FROM EXTERNAL PROVIDER;

ALTER ROLE db_datareader ADD MEMBER [eshop-dev-publicapi];
ALTER ROLE db_datawriter ADD MEMBER [eshop-dev-publicapi];
ALTER ROLE db_ddladmin ADD MEMBER [eshop-dev-publicapi];
```

**Important:** Execute this script in both `CatalogDb` and `IdentityDb` so that both App Service identities receive the required permissions in each database.

The Azure SQL logical server must have a Microsoft Entra administrator configured, and the executing identity must have sufficient permissions to create external-provider users and assign database roles.

## 5. Verify User Creation and Role Assignments

After recreating the users, execute the following query to verify their creation and assigned database roles.

```sql
-- Verify both Managed Identity users and their assigned database roles.

SELECT
    u.name AS PrincipalName,
    u.type_desc AS PrincipalType,
    u.authentication_type_desc AS AuthType,
    u.create_date AS CreatedDate,
    STRING_AGG(r.name, ', ') WITHIN GROUP (ORDER BY r.name) AS AssignedRoles
FROM sys.database_principals u
LEFT JOIN sys.database_role_members drm
    ON u.principal_id = drm.member_principal_id
LEFT JOIN sys.database_principals r
    ON drm.role_principal_id = r.principal_id
WHERE u.name IN (
    N'eshop-dev-webmvc',
    N'eshop-dev-publicapi'
)
GROUP BY
    u.name,
    u.type_desc,
    u.authentication_type_desc,
    u.create_date;
```

The expected result should contain two database principals:

| Principal | Expected roles |
|---|---|
| `eshop-dev-webmvc` | `db_datareader`, `db_datawriter`, `db_ddladmin` |
| `eshop-dev-publicapi` | `db_datareader`, `db_datawriter`, `db_ddladmin` |

Repeat the verification in both databases.

## 6. Restart the App Services

After successfully recreating the database users and assigning their roles, restart both App Services.

Using Azure CLI:

```powershell
# Restart the Web MVC App Service.
az webapp restart `
    --name eshop-dev-webmvc `
    --resource-group eshop-dev-rg

# Restart the Public API App Service.
az webapp restart `
    --name eshop-dev-publicapi `
    --resource-group eshop-dev-rg
```

Restarting the applications allows them to establish fresh database connections using their Managed Identities.

## 7. Expected Outcome

After completing these steps:

- Both old database users are removed.
- Both Managed Identity users are recreated through Azure SQL's native `FROM EXTERNAL PROVIDER` functionality.
- The database users have the correct identity information.
- Both identities receive the required database roles in `CatalogDb` and `IdentityDb`.
- Both App Services are restarted to establish fresh database connections.

This procedure resolved the Managed Identity database authentication issue encountered during the Terraform deployment.
